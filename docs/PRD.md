## 1. Summary

Snapper is a macOS menu bar utility with three global shortcuts:

| Default shortcut | Action |
|---|---|
| ⌘⇧4 | Capture a screen area (or a window) as a screenshot |
| ⌘⇧5 | Record a screen area (or a window) as a video |
| ⌘⇧6 | Capture a screen area (or a window) and open it in the annotation editor |

All three shortcuts can be changed in Settings.

## 2. Goals and non-goals

**Goals**
- Fast, keyboard-driven capture that feels native to macOS.
- A minimal annotation editor covering the common cases: rectangles, arrows, and text.
- No configuration needed beyond the first-run permission steps.

**Non-goals (v1)**
- Mac App Store distribution and sandboxing.
- Floating thumbnail previews after capture.
- GIF export, audio from system output, highlighted clicks.
- Annotation tools beyond rectangle, arrow, and text (no blur, highlighter, crop, or numbered steps).
- Selections that span more than one display.
- JPEG output and window drop shadows.

## 3. Platform and technical constraints

- **Minimum OS:** macOS 15 (Sequoia). Developed on macOS 26 with Xcode 26 and Swift 6.
- **Language/UI:** Swift 6. AppKit for the menu bar item, selection overlays, recording overlay, and annotation canvas. SwiftUI for the Settings and onboarding windows.
- **Capture:** ScreenCaptureKit for both screenshots (`SCScreenshotManager`) and recording (`SCStream` plus `SCRecordingOutput`).
- **Hotkeys:** [`KeyboardShortcuts`](https://github.com/sindresorhus/KeyboardShortcuts) via SwiftPM. This is the only third-party dependency.
- **Launch at login:** `SMAppService.mainApp`.
- **Distribution:** direct, not sandboxed, signed with the developer's certificate. The app is an agent app (`LSUIElement = YES`) with no Dock icon.
- **Project:** Xcode project generated by XcodeGen from `project.yml`. The repo is tracked in git.

## 4. Menu bar item

- Icon: SF Symbol `camera.viewfinder`. While recording, it changes to a red `record.circle`.
- **Left-click** opens a menu:
  - Screenshot (⌘⇧4)
  - Record (⌘⇧5)
  - Annotate (⌘⇧6)
  - —
  - Settings…
  - Quit Snapper
  
  The shortcuts shown always reflect the current bindings.
- **Right-click** opens the Settings window directly.
- **While recording**, clicking the icon (either button) stops the recording and saves it.

## 5. Selection overlay (shared by all three modes)

- When a shortcut fires, a borderless full-screen overlay appears on **every** connected display.
- **Rectangle mode** (default):
  - The cursor becomes a crosshair.
  - Dragging draws a rectangle. The area outside it is dimmed, and a live **W × H** readout in points appears near the cursor.
  - A rectangle is confined to the display where the drag started.
  - A click without a drag does nothing. A drag smaller than 4 × 4 points counts as a click: nothing is captured and the overlay stays open.
- **Window mode:**
  - **Space** toggles between rectangle and window mode, either before or during a drag. Toggling during a drag discards that drag; switching back to rectangle mode starts a fresh drag.
  - The window under the cursor is highlighted, and clicking selects it.
  - Our own windows and system UI that can't be captured are excluded from window hit-testing.
- **Esc** cancels at any time and closes the overlay without doing anything.
- After a selection, the overlay is removed before capture so it never appears in the output.
- While the overlay is open, all Snapper shortcuts are ignored.
- If a display is connected or disconnected, or its arrangement, resolution, or scale changes while the overlay is open, the selection is cancelled.

## 6. Feature: Screenshot (⌘⇧4)

1. The user selects a rectangle or a window (section 5).
2. The image is captured:
   - Format: PNG at native pixel resolution (2× on Retina), with no cursor.
   - Window captures contain only that window, with no shadow, even if other windows cover it.
3. The output depends on the **Screenshot destination** setting: *Save to file*, *Copy to clipboard*, or *Both*. The default is **Both**.
4. The shutter sound plays if it is enabled (on by default). It is the system screen-capture sound (`/System/Library/Components/CoreAudio.component/Contents/SharedSupport/SystemSounds/system/Screen Capture.aif`), falling back to `NSSound(named: "Grab")`, then `"Pop"`, if that file is missing.
5. **Errors:** if Screen Recording permission is missing, the onboarding window opens (section 11). Any other capture failure shows a short alert with the error.

## 7. Feature: Recording (⌘⇧5)

1. The user selects a rectangle or a window (section 5). Recording **starts immediately**, with no countdown.
   - **Window mode** records only that window. The capture follows the window as it moves, and anything covering it is excluded.
2. **Output format:** `.mp4`, H.264, native resolution, 30 fps, cursor visible. Source bounds snap to the display pixel grid; each output dimension rounds down to an even pixel count for H.264, without rescaling rectangle captures. Window recordings use the starting content size × its ScreenCaptureKit pixel scale, rounded to whole pixels and then down to even dimensions (minimum 2 × 2). Their output dimensions remain fixed; resizing the window or moving it to a display with a different scale fits the content into that frame while preserving its aspect ratio, with letterboxing as needed.
   - Audio: the microphone is recorded only if the *Record microphone* setting is on (off by default). System audio is never recorded. If microphone permission is missing or no input device exists at recording start, record video only without prompting or showing an alert.
3. **Recording overlay** (excluded from the recording):
   - A floating pill below the recorded area, or above it if there is no room below. If there is no room above either (for example, a full-screen selection), it is placed inside the area, near its bottom edge. It shows `elapsed time · Stop · Cancel` and stays on the recorded area's display.
   - A thin dashed border marks the recorded area.
   - In window mode, the pill and the border follow the window as it moves (its frame is polled about 4 times per second). Minimizing, hiding, or moving the window off-screen keeps recording; hide the border and keep the pill reachable at its last position, restoring the border when the window returns.
   - Errors: if Screen Recording permission is missing, the onboarding window opens. Any other failure to start or write the recording shows a short alert with the error. On a write failure, preserve and reveal a non-empty partial file; delete an empty file. Always show the error alert.
4. **Stopping and cancelling:**
   - **Stop** saves the file. Pressing ⌘⇧5 again or clicking the menu bar icon does the same.
   - **Cancel** discards the recording immediately without confirmation.
   - Esc does **not** cancel a recording.
   - ⌘⇧4 and ⌘⇧6 are ignored while a recording is in progress.
   - If the recorded window closes, or in rectangle mode the recorded display is disconnected, the recording stops and is saved as if Stop had been pressed. In window mode, continue following the window when macOS moves it to a remaining display after disconnection.
   - Quitting while recording stops and saves the recording before the app exits.
5. After saving, Finder opens the save folder with the new file **selected** (`NSWorkspace.activateFileViewerSelecting`). Recordings are not copied to the clipboard.

## 8. Feature: Annotate (⌘⇧6)

### 8.1 Capture and window
- The capture works exactly as in section 6, but instead of being saved or copied, the image opens in a new **annotation window**.
- The annotation window:
  - is a normal, resizable window with a toolbar on top;
  - initially scales the image to fit about 80% of the screen and never upscales it;
  - can be open in several copies at once.
- Closing a window with changes that have not been saved or copied asks **"Discard changes?"**.
- Quitting Snapper while one or more annotation windows have unsaved changes asks once: **"Quit and discard N unsaved annotations?"**.

### 8.2 Toolbar
| Control | Shortcut | Behavior |
|---|---|---|
| Select/Move | V | Click a shape to select it, drag the shape to move it, drag its handles to resize it |
| Rectangle | R | Outline-only rectangle. Shift constrains it to a square |
| Arrow | A | Straight line with a filled arrowhead. Shift snaps the angle to 45° |
| Text | T | Click to place a text box (see 8.3) |
| Color | — | Preset swatches (red, orange, yellow, green, blue, purple, black, white), plus a "+" button that opens the system color picker |
| Stroke width | — | S / M / L = 2 / 4 / 8 image points. The arrowhead scales with the stroke width |
| Save | ⌘S | Save dialog pre-filled with the default folder and file name |
| Copy | ⌘C | Copies the flattened image to the clipboard. The window stays open |
| Undo / Redo | ⌘Z / ⇧⌘Z | Covers every edit, including moves, resizes, color changes, and text edits |
| Delete | ⌫ | Deletes the selected shape |

- The active tool **stays selected** after each shape is drawn.
- Rectangle drags with either dimension below 3 view points and arrow drags shorter than 3 view points create no shape, at any zoom.
- Rectangles are selected only near their outline (within half the stroke width plus 4 view points); their empty interior is not a hit.
- Arrowhead length is 3 × stroke width + 8 image points, and its width is 80% of that length. For shorter arrows, clamp the head length to the arrow length and its width to 80% of that.
- The last-used color is remembered between sessions. The initial default is **red**.
- The last-used stroke width is remembered between sessions. The initial default is **M**.
- Esc, when no text box is being edited, deselects the selected shape. It never closes the window.
- Changing the color or stroke width while a shape is selected applies the change to that shape.
- Resize handles: the four corners of a rectangle and the two endpoints of an arrow.
- ⌘C copies the image only when no text box is being edited. While editing, it copies text as usual.

### 8.3 Text
- Clicking with the Text tool places a text box and starts editing.
- Enter adds a new line. **Esc** or clicking outside the box commits the text, and empty text boxes are removed.
- Double-clicking existing text edits it again. A single click on existing text with the Text tool also edits it, with the caret at the clicked character.
- Text uses a bold system font in the current color. Its size follows the stroke width: S = 16pt, M = 24pt, L = 36pt, in image points.
- Text has a thin contrasting outline (white around dark text, black around light text) and no background.

### 8.4 Export
- The flattened output is rendered at the image's **full pixel resolution**, not at the window's display scale.
- Shapes are stored in image coordinates, so window zoom never changes the output.

## 9. Files and naming

- Default save folder: **`~/Documents/Screenshots`**, created on first use if it doesn't exist. It can be changed in Settings.
- Screenshots and recordings share the same folder.
- File names:
  - `Screenshot 2026-11-02 at 19.18.04.png`
  - `Recording 2026-11-02 at 19.18.04.mp4`
  
  Screenshots use the capture time, and recordings use the time the recording started.
- On a name collision, ` (2)`, ` (3)`, and so on are added to the name.
- If the save folder can't be created or isn't writable, an alert says "Couldn't save to <folder>" and offers a **Choose Folder…** button. With the *Both* destination, the image is still copied to the clipboard. Choosing a folder updates the setting and retries saving the pending screenshot once. The alert uses a tilde-abbreviated folder path, offers Cancel, and includes the system error details. Other screenshot failures use the title "Couldn't take screenshot".

## 10. Settings window (SwiftUI)

**General**
- Launch at login (default **off**)
- Save folder (folder picker; default `~/Documents/Screenshots`)
- Screenshot destination: Save to file / Copy to clipboard / Both (default **Both**)
- Play shutter sound (default **on**)

**Shortcuts**
- One recorder field each for Screenshot, Record, and Annotate (defaults ⌘⇧4 / ⌘⇧5 / ⌘⇧6).
- A warning appears when a binding conflicts with an enabled macOS screenshot shortcut, with a button that opens System Settings.
- A binding already used by another Snapper shortcut is rejected.

**Recording**
- Record microphone (default **off**). Turning it on requests microphone permission. If permission is denied, the toggle switches back off and a note appears with an **Open System Settings** button.

## 11. First run and permissions

- At launch, the app checks for **Screen Recording** permission and whether the **macOS screenshot shortcuts** (⌘⇧4/⌘⇧5) are enabled. If either step is needed, it shows a single **onboarding window**:
  1. Grant Screen Recording. A button opens System Settings → Privacy & Security → Screen & System Audio Recording. The window notes that macOS may require relaunching Snapper.
  2. Turn off the macOS screenshot shortcuts. A button opens System Settings → Keyboard → Keyboard Shortcuts → Screenshots.
- Step 2 counts as done when no *enabled* macOS screenshot shortcut collides with a *current* Snapper binding. Rebinding Snapper away from the system shortcuts also satisfies it.
- The onboarding window appears at each launch until both steps are done or the user dismisses it with "Don't show again".
- If a shortcut fires without Screen Recording permission, the onboarding window opens instead of the overlay.
- Microphone permission is requested only when *Record microphone* is turned on.

## 12. Acceptance criteria (v1)

- [ ] The app runs as a menu bar app only, with no Dock icon.
- [ ] Left-click opens the menu and right-click opens Settings.
- [ ] ⌘⇧4 rectangle capture produces a PNG at 2× on Retina, saved to the folder and copied to the clipboard by default.
- [ ] Pressing Space switches to window mode, and the resulting capture contains only that window with no shadow, even when it is covered.
- [ ] Esc cancels the overlay on every display.
- [ ] With multiple displays, the overlay covers all of them and the capture comes from the display where the drag started.
- [ ] ⌘⇧5 records an `.mp4` of the selection that contains neither the overlay pill nor the border.
- [ ] Stop (button, ⌘⇧5, or menu bar icon) saves the file and reveals it in Finder. Cancel discards it.
- [ ] ⌘⇧6 opens the annotation editor, where all tools, shortcuts, undo/redo, delete, and recoloring work.
- [ ] Saved or copied annotated images keep full resolution.
- [ ] All three shortcuts can be rebound in Settings and take effect immediately.
- [ ] The onboarding window appears when permission is missing or the system shortcuts conflict.
- [ ] Launch at login works from Settings.
- [ ] The default save folder is created when it is missing. An unwritable folder shows "Couldn't save to <folder>" with **Choose Folder…**.
- [ ] Window recordings follow the window, and closing the recorded window stops and saves the recording.
- [ ] Closing a modified annotation window asks "Discard changes?", and quitting with unsaved annotations asks once.
